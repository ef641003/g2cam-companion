G2 カメラアプリ（Even アプリ内 WebView）の相棒になる小さな Android アプリ。

- カメラを**フォアグラウンドサービス（種別 camera）**で保持するので、**スマホの画面が消えていても**映像の配信と撮影が止まらない
- `127.0.0.1:8787` のローカル HTTP で G2 カメラアプリに映像を渡す（WebView の `getUserMedia` 許可が不要になる）
- 撮影した写真は、アプリで選んだ**保存先フォルダ**（既定は**「写真」アプリの `DCIM/G2Camera`**）に直接保存される（NAS 同期アプリなどにもそのまま乗る）

通信仕様は `../docs/companion-protocol.md`。G2 カメラアプリ側は起動時に `GET /status` を見て、返れば自動でこの経路を使う。

> **状態**：GitHub Actions でビルドしている（`ef641003/g2cam-companion`）。ビルドのたびに単体試験も走り、遡り録画のつなぎ合わせはエミュレーターでも確かめている。実機での確認はこれから（気づいたことはログを添えて伝えてもらえれば直す）。

## ビルド（GitHub Actions）

JIMTOF 案内アプリと同じ方式。`companion-android/` を**単独のリポジトリ**として push する（`.github/workflows/build.yml` がこのフォルダ直下にあるため）。

1. GitHub に新しいリポジトリを作る（例：`g2cam-companion`。Actions を使うため、ビルドの間は公開にして、終わったら非公開に戻す運用）
2. このフォルダの中身を push する
   ```bash
   cd companion-android
   git init -b main && git add . && git commit -m "G2 camera companion"
   git remote add origin https://github.com/<ユーザー名>/g2cam-companion.git
   git push -u origin main
   ```
3. リポジトリの **Actions** タブで「APK をビルド」が走る → 終わったら成果物 `g2cam-companion-debug` をダウンロード（zip の中に `app-debug.apk`）
4. APK をスマホに入れてインストール（「提供元不明のアプリ」を許可）

Android Studio で開いてビルドしても同じ（Gradle 8.7 / JDK 17）。

## 待機モード（G2 カメラを開いたら自動でカメラを開始）

1. アプリで「待機モード」をオンにする（通知が出て常駐する。127.0.0.1:8788 で起動要求を待つだけで、カメラは使わない）
2. 「他のアプリの上に表示」を許可する（裏から画面を出してカメラを始めるために必要）
3. G2 カメラを開くと `POST /launch` が届き、透明な画面が一瞬出てカメラが始まる（G2 カメラを終了すると自動で止まる。待機は残る）

端末の再起動後も、待機モードがオンなら自動で再開する。vivo / OriginOS ではバックグラウンドの許可と最近のタスクのロックも要る。

## 使いかた

1. アプリを開き、カメラ権限と通知を許可
2. **「電池の最適化から除外する」** を押して許可。vivo / OriginOS ではさらに「アプリ情報」→ 電池 →「バックグラウンドでの高消費電力を許可」をオンにし、最近のタスクでこのアプリをロックしておく
3. **G2 カメラを開く**。コンパニオンが動いていなければ、G2 カメラが `g2cam://start` で自動起動する（一瞬このアプリが前面に出て、Even アプリに戻る）。起動しないときは、このアプリを開いて「カメラを開始」を押してから G2 カメラを開く（**この画面を出したまま**押す。Android 11 以降、バックグラウンドからはカメラ付きサービスを始められない）
4. G2 カメラの診断欄に「コンパニオンアプリ」と出れば成功
5. 画面を消しても、通知が出ている間は映像と撮影が続く
6. **G2 カメラを終了すると、コンパニオンのカメラも自動で止まる**（メガネの終了確認で「はい」、またはアプリを閉じたとき。G2 カメラが落ちた場合も、2 分間応答がなければ止まる）。手で止めるときは通知の「停止」かアプリの「停止」

## 録画

G2 カメラのメニュー「動画 録画/停止」（またはスマホ画面の「● 録画」）で録画が始まり、メガネには「● 録画 0:12」と出る。**録画中のタップは録画停止**（スマホの「撮影」ボタンは録画中も静止画を撮る）。

- 動画は **`DCIM/G2Camera/G2_….mp4`** に保存され、写真アプリに出る（NAS 同期にも乗る）。G2 カメラのギャラリーにはサムネイルと長さが並び、「保存先へ送る」でコンパニオンから取り寄せて PC や Google Drive に送れる
- 音声はマイクの許可があるときだけ入る（アプリ起動時に聞かれる。断っても無音で録画できる）。許可を後から与えたときは、コンパニオンを一度「停止」して始め直す
- 画質・最長時間・音声の有無は G2 カメラの設定（既定：フル HD・10 分・音声あり）
- 録画の開始・終了のときに映像が 0.5 秒ほど途切れる（カメラの構成を切り替えるため）。端末によっては録画中に静止画が撮れない、またはライブ映像が止まる（G2 カメラのログに出る）
- 通知の「録画停止」でも止められる。G2 カメラを終了したときやコンパニオンを停止したときは、録画を保存してから止まる

### G2 録画アプリとの組み合わせ（0.1.11）

- **すぐ始まる録画**：G2 録画を開くと「録画の準備」が届き、待機中から配信＋録画の組み方にしておく。タップしてすぐ録画が始まり、ライブ映像も途切れない（通知に「録画の準備ができています」）。G2 録画を閉じると元に戻る
- **区切り録画**：G2 録画の「1 本の長さ」ごとに、止めずに次のファイルへ続ける（つなぎ目は 1 秒ほど欠ける）
- **見張りと自動停止**：電池の温度・発熱・空き容量を 5 秒ごとに読み、G2 録画の「止める温度」（既定 47 度）を超えたとき・空きが 500MB を切ったとき・発熱が「危険」の段階になったときは、録画を保存して止める。理由はメガネに出る

### 遡り録画（この画面でオン/オフ。既定はオフ）

録画を始めたとき、その**直前の数秒（5 / 10 / 15 / 30 秒から選ぶ）も 1 本の動画に入れる**。「あっ」と思ってからタップしても、その瞬間が残る。

- オンにすると、G2 録画を開いている間はアプリ内に短い切れ端を録り続ける（カメラと、音声ありならマイクも使い続けるので、**電池の減りと発熱が増える**。マイクの使用中の表示も出たままになる）
- タップしたら今の切れ端をそのまま本番の録画にする（つなぎ目なし）。止めたあと、直前の分とつないで 1 本に書き出す（再エンコードしないので画質は落ちない。長い録画ほど数十秒かかる。書き出し中も次の録画はできる）
- つなげないときは、本番の動画と直前の分（`…_pre.mp4`）を別ファイルで残す。書き出しの途中でアプリが止まっても、次にコンパニオンを開いたときに書き出し直す
- スマホが熱いとき・空き容量が少ないときは録りためを休む（この画面とメガネに「休止」と出る）
- 1 本目は書き出しまでアプリ内に置くので、同じだけの空き容量が要る（足りなくなりそうなら早めに区切るか止める）

## スマホの負荷（0.1.12）

「待機中なのに熱くなってカクつく」ときは、この画面の **「負荷」** の欄と **「ログ」** を見る。

- **負荷**：`CPU 3%（5 分平均 2%・最大 12%）　忙しいスレッド: …` は**このアプリ自身**の CPU（1 コアの %）。待機中なら 0〜2% が普通。ここが高い（20% 以上）なら、このアプリに原因がある。忙しいスレッドの名前（`g2cam-standby` や `NanoHttpd…` など）がそのまま手がかりになる。続く行はスマホの電池温度と発熱の段階（Android が報告する 0〜6。3 以上で OS が動作を遅くする）
- **このアプリの CPU は低いのに熱い**ときは、原因はほかにある。設定 → 電池 → 電池使用量（アプリ別）で、`G2 カメラ コンパニオン` と `Even`（Even Realities）アプリのどちらが減らしているかを見る。G2 アプリを閉じたつもりでも Even アプリの中で動き続けていることがある（G2 アプリの画面の「診断」で「取り込み元」が `webrtc` ならスマホのカメラを WebView が使っていて重い）
- **ログ**：起動・停止・起動要求・カメラの開閉・発熱の段階の変化・「待機中なのに CPU が高い」の検知が時刻つきで残る。「ログを共有」で LINE やメールに貼れる（Claude に貼れば読める）
- **比べ方**：待機モードの設定「透明な窓を出し続ける」を切って、同じ使い方で熱さを比べる（切ると、Android 15 以降では裏から起動できないことがある。その場合は起動要求のときだけ窓を出す）

設定「スマホの負荷を抑える」の項目は録画の画質に関わらない：配信の上限 fps（既定 15。30 は以前の動き）、要求が無ければカメラを閉じる（既定オン）、待機中はセンサー 15fps（既定オン）、静止画の高画質は撮影の前後だけ（既定オン。最初の 1 枚が 1 秒ほど遅れる）。

## ズームとレンズの自動切替

G2 カメラの上下スワイプで、端末のレンズ側ズーム範囲に合わせた段階（0.5 / 1 / 2 / 3 / 5 / 10 倍のうち範囲に入るもの）を順に切り替える。倍率はコンパニオンが CameraX のズーム比として設定するので、**超広角・標準・望遠を持つ端末では、OS が倍率に応じてレンズを自動で切り替える**（0.5 倍が超広角、2 倍以上が望遠、など）。

- 使えるのは「アプリに論理カメラとして 1 つに見える」端末。Pixel や多くの Android 端末はこれに当たる
- 端末が超広角などを別カメラとして隠している（ズーム範囲が 1.0 以上しかない）場合は、超広角には切り替わらず、G2 カメラのデジタルズームになる。対応しているかは G2 カメラの診断欄「取り込み元」の「レンズズーム x…〜x…」で分かる

## fps について

コンパニオンはカメラの映像を最大 30fps で取り込み、G2 カメラは新しいフレームが来るたびにすぐ受け取る（長いやり取りの待ち時間は無い）。ただし**メガネへ送れるのは BLE の速さまで**（実測で 1 枚 100〜150ms、5〜9fps）なので、メガネに出る fps は 30 にはならない。速くしたいときは G2 カメラの設定「プレビューの大きさ」を小さくする（50% で枠が 1/4 の画素数になり、送信が速くなる）。

## 既知の限界

- 画面 OFF 中もカメラが動くのは、**画面が出ている間にサービスを始めた**場合だけ。端末が再起動したりシステムにサービスを落とされたら、もう一度アプリを開いて開始する（自動再開はしない。裏からの再開は Android が拒否するため）
- 端末の向きは加速度センサーで追従するが、機種によっては画面 OFF 中にセンサーが止まり、向きが固定されることがある
- 映像は長辺 320px の JPEG（G2 の表示が 288×144 までなのでこれで足りる）。フロントカメラは鏡像にしていない
- 他のアプリがカメラを使い始めると Android がこのアプリのカメラを奪うことがある（その場合は開始し直し）
